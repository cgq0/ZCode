# cgq0/ — fork 维护者专属命名空间

> **定位**：`cgq0/` 是本 fork（github.com/cgq0/ZCode）维护者的专属目录，存放与上游无关的文档和脚本。
> 上游（zai-org/ZCode）**永远不会有**这个目录，所以这里的文件与上游合并冲突面为零。
> 反过来也一样：**上游代码不引用本目录的任何内容**，不要在 `packages/`、`apps/`、`scripts/` 里 import 或 require 本目录的文件。

## 文件树

```
cgq0/
├── README.md            # 本章程：谁写、写哪、规矩是什么（写任何东西前先看这里）
├── docs/
│   ├── TODOs.md         # 待办：一行一条 + 指向论证的指针，保持薄
│   ├── diary/           # 开发日志，append-only，永不改历史
│   │   └── YYYY-MM-DD.<机器别名>.md
│   └── plan/            # 批次计划：YYYY-MM-DD-<序号>-<主题>.md
└── scripts/
    └── ai-commit.sh     # 带 X-AI 署名 trailer 的 commit 包装器（本 fork 的唯一 commit 入口）
```

## commit 规则（强制）

本 fork 的**所有 commit** 必须通过包装器提交，自动附加 `X-AI` 署名 trailer（LLM 模型名 @ harness 名/版本）：

```sh
cgq0/scripts/ai-commit.sh -F <消息文件>          # 常规提交
cgq0/scripts/ai-commit.sh --amend -F <消息文件>   # 修补
```

- 身份来自系统提示词和环境变量，例如，harness是 pi 的话这些信息可以解析自 `PI_MODEL` / `PI_CODING_AGENT` / `pi --version`，其他 harness 要根据具体情况调整，无法解决就问用户。
- 解析不出非 human 身份时**拒绝提交**（退出码 2），宁可失败不可错标。
- **merge commit 不署名**：合流是管道操作不是创作内容，计入 AI 占比会虚增统计。
- 已带 `X-AI:` 的消息（amend、cherry-pick 重放）不重复追加。
- 纯人工 commit 不走脚本也不会被错标——没有钩子，没有默认状态污染，trailer 只由脚本显式写入。

## 日记规则

1. **一个文件 = 一台机器 × 一天**：`YYYY-MM-DD.<机器别名>.md`。
2. **机器别名固定用平台名**：`mac` / `win` / `lin`（无需更细的区分，也无需维护映射表）。不要升级到真实主机名/Tailscale 名等更细的标识——公仓永久存档，平台名定位文件已足够，再多就是基础设施指纹泄露。
3. **append-only**：写今日条目前先 `git fetch` 并确认 origin 上今天本机的文件是否已存在（落后看不到别的机器同日文件曾导致 add/add 冲突）；存在就追加，永不覆盖、永不改历史。
4. **时间戳跑 `date`**，禁止脑补"上午/下午/深夜"。
5. **公仓卫生**：不写凭据、token、内网/服务地址、真实姓名、邮箱；引用外部 issue/链接没问题。

## TODOs 规则

- 一行一条，可执行动词开头，后面跟指针（`——` 指向 diary/plan/issue 里的论证）。
- 做完不删行留虚无历史：移入对应日记或 plan 条目后删除，溯源靠日记 append-only 历史。

## plan/ 规则

- 每个开发批次一个文件：`YYYY-MM-DD-<序号>-<主题>.md`（序号为当日批次号，从 01 起）。
- 计划文件写：背景、目标、步骤、验证方式。执行中的偏差随手批注在文件里，结论性教训沉淀回日记。

fork 级"为什么这么做"的决策，新的加在最下面：

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-10-20 | fork 专属文件全部收进 `cgq0/` 顶层目录 | 本 fork 的改动几乎不会被上游合并；专属文件混进上游文件树会让每次合并都冒出冲突。以 git 用户名建命名空间后，合并冲突面为零 |
| 2026-10-20 | 日记机器别名固定用平台名 `mac`/`win`/`lin` | 主机名属于基础设施指纹。平台名定位文件已足够，不泄露硬件型号/网络信息，也无需维护脱敏映射表 |
| 2026-10-20 | commit 署名用包装器脚本而非 git hooks | 上游 husky 独占 `core.hooksPath` 且每次 `pnpm install` 重置；往 `.husky/` 加钩子文件会污染上游文件树。包装器纯 `cgq0/` 内，merge 无感，代价是纪律（所有 commit 走脚本） |
