# 2026-10-24 (mac)

## 17:09 — 前台双高 CPU 全链路定罪：occlusion 设置落地（Electron 41.2.0）+ 桌面卡死事故复盘

**用户输入的体感**：最小化后 CPU 就下来；窗口放最前面 `ZCode Helper` 与
`ZCode Helper (Renderer)` 持续双高，而"整个窗口重绘就几行字和一个转圈圈"；直感
"一直在前面迟早会出事"——后半句当天就应验了（见下）。

**测量**（官方 3.16.3，Electron 41.0.3，Intel x64 内建 Retina 2560x1600 单屏单 Space）：

- `top -l 3 -s 2` 瞬时：流式期间 Renderer 46.8%→54.7%、GPU 62.6%→81.9%；
  流式结束（zcode-cli 掉到 1.2%）后安静"转圈圈"态仍有 **GPU 46.7% / Renderer 27.4%**，
  注销重登后立刻复现（新 PID 同样 49.2%/30.2%）。`ps %CPU` 是生命周期衰减均值，判读
  必须瞬时（延续 10-23 教训）。
- 进程映射：Activity Monitor 里无后缀 `ZCode Helper` = `--type=gpu-process`。
- `sample 4s`：GPU 主线程 37% 样本在 `__CFRunLoopDoSources0` 内进 Intel 驱动编码
  Metal 渲染命令（`IGAccelRenderCommandEncoder::drawIndexedPrimitives`、
  `programPipeline`、`IOSurfaceBindAccel`）——OOP 光栅化+合成的海量小 draw call，
  即"每帧全量重合成"；Renderer 主线程 28% 在 V8 JIT（无法符号化，同 10-23 结论），
  Compositor 11%，DedicatedWorker/Media 全空闲。4 条无名高样本线程实为
  `__workq_kernreturn` 空闲池，勿被样本数骗。
- 硬件加速开着（setting.json `desktopChromiumHardwareAccelerationEnabled: true`），
  排除软件合成。

**桌面卡死事故**：14:26 与 14:32 两次 `screencapture -x` 输出**字节数完全相同**
（9950222），且画面只有壁纸+菜单栏（前台应用显示"系统设置"）——不是窗口在别的
Space（用户确认 ZCode 一直在最前面、单屏单 Space），而是 **WindowServer 已停止合成
应用窗口（桌面半冻结）**，而 Chromium 因 occlusion 被禁对"没人看"毫无反应，仍在以
47-82% 渲染，与 WindowServer 挤同一块 iGPU。用户随后 iShot 截图成为最后一根稻草，
桌面彻底卡死→当前用户被注销（iShot 截图未落盘，大概率只进剪贴板）。教训两条：
①"截屏拿不到窗口内容+多次截屏字节数相同"是 WindowServer 半冻结的廉价信号，
GPU 挤压场景可以先看这个；②连续 push GPU 的 Electron 应用在 Intel iGPU 上真能把
桌面会话拖死，"体感迟早出事"要当运维事实对待。

**根因两层（本次分开治）**：

- A（不可见照烧）：Electron ≤41.1.x 在 `shell/browser/feature_list.cc` 硬编码把
  `MacWebContentsOcclusion` 追加进 disable 串，且 FeatureList 在 `PreBrowserMain`
  （App JS 之前）冻结；Chromium 规则"同名 feature 同时在 enable/disable 列表一律
  disabled"→ App 内 appendSwitch/进程参数/relaunch 全都救不回来。PR #50579 的移除
  落在 v41.2.0（逐 tag 已核，41.1.1 仍有、41.2.0 清零）。最小化走原生 miniaturize
  通知路径，与 occlusion 无关，所以"最小化降、其他不可见场景不降"。
- B（前台也烧）：`reasoning.tsx:332` 思考中标签用 `.animated-gradient-text` 流光
  （`background-clip: text` + `background-position` 动画——非合成器友好属性，每帧
  重绘文字），`isStreaming` 全程跑；`.tool-call-progress-indeterminate` 1.2s 无限
  扫光同理。任一常驻动画都逼 Chromium 60fps 全窗口重合成，弱 iGPU 上这就是
  40-80%。`FloatingParticles` 只挂 Highspeed 激活页，排除。

**A 已落地**（spec：`docs/desktop/mac-occlusion-throttling.md`）：

- Electron pin 41.0.3→41.2.0（同 Chromium/Node/ABI 补丁线；pnpm install 首次挂死
  32 分钟、无子进程活动，杀掉后 `ELECTRON_MIRROR=npmmirror` 50s 完成）。
- 设置 `desktopMacOcclusionThrottlingEnabled` 默认开：object/patch 双 schema +
  `protocol.ts` 的 `AppSettings`（手写接口与 zod 双轨，漏一边 typecheck 才发现）。
- main whenReady 启动协调：设置只表达"下次启动期望"，argv 不一致则在创建窗口前
  `prepareAppQuit` + `relaunch({args})` 一次；注入
  `--disable-features=MacWebContentsOcclusion` + 哨兵
  `--zcode-mac-occlusion-injected`；**用户自带 feature 参数一律不接管**；非 darwin
  no-op。不用 JS `appendSwitch`（FeatureList 已冻结，写了无效）。
- 新模块走 adopt 流程登记 `desktop-mac-occlusion`（`src/main/mac-occlusion/`，契约
  五件套；直接放 `src/main/` 会被 unmanaged-new-file 规则拦——存量文件靠 merge-base
  豁免，新文件必须 adopt，这是本次学到的架构检查行为）。
- 设置 UI 完全对齐硬件加速先例（macOS 门控行、requiresRestart toast、中英 i18n）。
- 验证：typecheck 过（默认 2GB 堆 OOM，`NODE_OPTIONS=--max-old-space-size=4096`）；
  lint 0 errors（8 条存量警告逐条核对不在本次 diff）；受影响 UT 49/49——单测抓出
  真 bug：用户裸传 `--disable-features=MacWebContentsOcclusion` 会被重复注入，修正
  为"哨兵在场才归我方管理"；architecture:check 0 违规。

**B（前台成本）**：证据已够定位嫌疑（流光+扫光），`steps()` 降频方案待实施；

## 19:40 — 打包版冒烟：遮挡节流实测闭环 + 打包链路两坑

**打包**：首次 `pnpm --filter @zcode/desktop exec electron-builder --mac --dir` 失败于
"Please specify 'version' in package.json"——electron-builder 26 在 `pnpm --filter exec`
下**不会自动加载** `electron-builder.config.js`（version 在配置 extraMetadata 里，来源
out/metadata/build-meta.json），必须显式 `--config electron-builder.config.js`。修正后
盯日志又发现它下载 `electron-v41.0.3-darwin-x64.zip`——**builder 配置里硬编码了
`electronVersion: "41.0.3"`**，升级 package.json pin 时漏了这里，打出来的包会静默
回退旧 runtime。已改 41.2.0 并加同步警示注释（`desktopElectronVersion`（:89）动态读
package.json 不受影响）。正确命令：

```sh
CSC_IDENTITY_AUTO_DISCOVERY=false pnpm --filter @zcode/desktop exec \
  electron-builder --mac --dir --publish never --config electron-builder.config.js
```
