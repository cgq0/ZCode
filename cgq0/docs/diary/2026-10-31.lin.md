## 21:56 — webapp「此电脑」建项目必报「设备已从项目列表移除」：根因闭合与修复（86071dcb）

（补记：本条写于 11-01，时间锚取 git 提交时间。）

**背景**：用户报告 zcode-serve 自托管 webapp 里新建目录/项目必报
「此设备已从项目列表移除，请重新选择设备。」（i18n `project.hostRemoved`，
消费点 project-sidebar/view.ts:269，对应服务端错误码
`remote-project.host-removed`）。同时安排了上游同步评估（见 11-01 lin 条）。

**根因链**（agent 调查 + 实机复现确认）：

1. standalone Server 存储的 owner 恒为 `remote:server:<serverId>`
   （node.ts createServerHostServices 强制），repository.saveProject 返回值
   携带 owner 身份而非 UI 提交的字面量 "local"。
2. 上游 ProjectCreation.saved 按桌面语义写死：返回 hostId ≠ "local" ⇒ 必须是
   prepareHost 已登记的远端设备，查 admittedHosts 不中即抛
   remote-project.host-removed。webapp 远端目录恒为空（remote service
   controller=false）、「此电脑」路径 prepareHost("local") 又不登记 → 必然抛错。
3. 项目实际已创建成功（侧栏可见），只是弹窗不关、草稿不导航，重试恒报同一错。
   归因：抛出逻辑是上游同步代码；使之可达的是 d53e646b（10-25 打通浏览器
   「此电脑」建项目），其 e2e 漏看了此报错。先前怀疑的 6110996a 无关（只 gate
   projectless 入口）。

**修复**（86071dcb，21:56:49）：沿 origin 能力位注入架构——web bootstrap 从
server-info serverId 派生 ownerHostId 注入 originServerCapabilitiesStore，
saved() 识别「返回 hostId 即 origin owner」时按本地收尾（不抛错、导航回
"local"）；桌面真远端设备守卫不变。spec：
docs/superpowers/specs/2026-10-31-standalone-server-local-project-creation.md。

**验证**：新回归测试在修复前代码上确认失败、修复后 88 用例全绿；隔离数据目录
的 staging zcode-serve 实机走查修复前（复现报错，截图存 cgq0/tmp/shots/）与
修复后（全流程通过）；typecheck（需 8G heap，根 OOM 为既有问题）/lint/
architecture check 干净。21:5x push 未做（用户随后确认，11-01 早上推送，
pre-push 全绿）。
