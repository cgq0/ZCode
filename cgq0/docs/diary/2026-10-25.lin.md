## 09:47 — fork 视觉身份批次：ZCode.fork 产品名 + 蓝底图标（与官方版可同装）

**背景**（mac 上与官方版的共存问题，三轮讨论收敛）：

1. fork CI（release.yml）桌面产物是 `ZCODE_ENV=production` 的 production 身份，
   appId/userData 与官方 `ZCode.app` 全同：拖进 /Applications 直接顶掉官方，
   换目录装也躲不开（冲突跟 bundle id / userData 走，与安装路径无关）。
2. 仓库自带 Preview 身份（`dev.zcode.app.preview`）能真并存，但它把 Electron
   userData 拆开（登录态/窗口状态分家）——与"数据共享本来就是期望功能"相反，弃用。
3. 收敛到需求本质：**要的是"可同装 + 可区分 + 数据共享"，不需要同时运行**。

**决策**：保持 production 身份（appId `dev.zcode.app`、userData `~/Library/
Application Support/ZCode` 都不动 → 登录态/任务/凭据与官方全共享，单实例锁天然
防止双开），只改两个显示层：产品名 `ZCode.fork` + 图标黑底换蓝底。Finder 里
`ZCode.fork.app`（蓝）与 `ZCode.app`（黑）名字图标双区分，互不覆盖。

**实现**：

- `desktop-product-identity.mjs` 新增 `ZCODE_DESKTOP_PRODUCT_NAME` 覆盖：只改
  productName（.app 名/菜单栏/About/${productName} 产物名），flavor/appId/
  AUMID/Linux 包名/userData 目录名全部保持 flavor 原值。未设或空白 = 原样返回
  冻结身份表对象（存量测试的 `toBe` 语义不破坏）；含路径分隔符构建期报错。
  名字故意取通用拼写而不是 ZCODE_FORK_*，让这个 diff 对上游像个正经功能。
- `cgq0/scripts/rebrand-icons.py`（fork 命名空间，lin 机跑，需 Pillow）：
  近黑低饱和背景（max≤0x40 且极差≤14）映射为纵向蓝渐变（#1D4ED8→#1E3A8A），
  按原亮度/BG_REF=0x19 缩放保留原图渐变、暗角与底部纯黑投影层次；白 Z
  （min≥0xC0）原样；中间调按亮度比例蓝白混合保抗锯齿；alpha 全程不动。
  icns/ico 从换色源图重生成；上游换图标后重跑即可。`--apply` 覆盖
  packages/desktop/build/ 下 16 个资产（icon/icon_windows/icon_installer ×
  png/icns/ico + icons/ 尺寸集；icon_windows 与 icons/1024 本是同一文件）。
- release.yml desktop 步骤注入 `ZCODE_DESKTOP_PRODUCT_NAME: "ZCode.fork"`，
  release notes 表格/安装说明/Gatekeeper 提示文案同步（改为"可同装互不覆盖，
  数据共享、同时只运行一个"）。
