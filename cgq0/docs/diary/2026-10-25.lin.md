## 12:55 — Web 自托管打通：standalone 模式 hostId "local" 归一（fork 补线）

开放"的红线保持）；桌面端 owner 即 "local" 行为等价；"local" 与省略 hostId

## 16:45 — zcode-serve 孤儿进程 bug：stop 杀壳不杀 node

上一批"断线"期间留下的证据暴露真 bug：清场时发现 3030 端口挂着**两个孤儿
实例**（127.0.0.1 与 tailscale IP 各一）——之前两次 `stop` 都报"已停止"，实际
node 进程没死。根因：sh 启动器 start 里 `apply_env nohup node ... &` 经函数
转手，`$!` 记的是包装子壳 pid，node 是它的孩子；stop 杀壳，node 变孤儿。
ps1 版无此问题（Start-Process -PassThru 直接给 node pid）。

修复（947e1a25）：env 前缀直写 nohup 行（nohup exec node → $! 即 node 本体）；
stop 后探测端口真释放并如实报告；start 前发现"无 pid 文件但端口被占"直接
exit 1，防止误报。全部路径实测：生命周期 + 端口实查 free + 防护路径 exit 1。
教训：后台启动的 `$!` 语义、pgrep -f 自匹配假象（两次误报"进程复活"）。
