## 08:56 — 内存泄露调查（静态排查第一轮）：一个实锤泄漏 + 一个渲染放大器；19G 口径存疑

用户复报：zcode-cli 跑不到 1 小时明显卡（打字慢、吐 token 约 1 词/秒），活动监视器「内存」列
19-20G 波动，问合理吗。结论：**不合理，但分两层**。

第一层：这台机器物理内存只有 8G（hw.memsize = 8589934592），macOS「内存」列是 phys/real
footprint（驻留 + 压缩），单进程被物理内存封顶，19-20G 基本不可能；且 V8 堆上限（SEA 默认，
8G 机器约 2G 级别）决定了纯 JS 堆冲到 19G 前就会 OOM 崩溃——用户没报崩溃。之前实测数据点
（昨晚 8h38m 会话 RSS 623MB）也远够不着。判断：19G 大概率是看错行/列/多选聚合，需要下次卡
时活体取证才能定案。

第二层：卡是真的，静态排查找到两个能解释渐进式变卡的缺陷：

1. **highlightCache 无界泄漏（实锤）**：`packages/tui/src/app-shiki-highlighter.ts:39`
   模块级 Map，无任何淘汰（只有 test reset 清空）；cache key 内嵌完整代码内容
   （`theme\0language\0lines.join("\n")`，56 行），值是分词后的 segment 数组（比源码更大）。
   会话里每个渲染过的 diff/代码块永久驻留；若流式期间逐行增长还会 O(n²) 造 key。
2. **转录全量 reconcile（渲染放大器）**：`app-transcript-components.tsx:81` 对全部消息
   `messages.map` 建元素，`viewportCulling` 只裁剪绘制不裁剪 React 协调，MessageRow 无
   memo——每个流式 delta 触发 O(转录长度) 的重建，转录越长每个 token 越慢，正好吻合
   「越用越卡、吐字变慢」。

已排除：modelIOCompactionStates（按 filePath 为 key、有 delete）、subagent 查询 Map
（函数局部）、web-tree-sitter（tui 源码零引用）、model-io 磁盘累积（单会话 64MB 硬上限，
实测最大 47MB）、TUI assistantMessageIdsByToolCallId（只存字符串 ID，量级 KB）。

修复方向（待用户确认后动代码）：highlightCache 加容量上限（LRU/TTL）；MessageRow memo 化 +
流式 delta 合帧（coalesce）。19G 定案协议：卡时别退出，`ps -o rss,vsz -p <PID>` +
`footprint <PID>` + `kill -USR1 <PID>` 开 inspector 取堆快照 + 活动监视器截图看列名。

## 22:38 — fork 构建版本标识落地：SemVer build metadata（`+`）从 git 自动推导

用户提出痛点：上游同一版本号（v0.17.0）对应多份代码/构建，fork 修没修 bug 的产物都叫
v0.17.0，无法区分。讨论后定案：用 SemVer build metadata 而非预发布后缀——`-revx` 会被
判为低于正式版（`>=0.17.0` 匹配不到），`#` 非法字符；`+` 后缀不参与优先级比较，既等于
0.17.0 又唯一标识构建。

实现（packages/cli/scripts/build.mjs）：`git describe --tags --long --dirty` 解析出
`cq.<n>.g<sha>[.dirty]` 附加到 package.json 版本后注入 `__CLI_VERSION__`；无 tag 回退
`cq.dev.g<sha>`，完全无 git 回退 `cq.dev`，任何 git 失败都不挡构建。关键取舍：tag 名不入
metadata（本仓库 tag 是 zcode-cli-v3.16.2 的 monorepo 风格，与 CLI 的 0.x 不同源，只有
提交距离+SHA 可信）；package.json 版本保持与上游同步不动，fork 身份只存在于构建产物。

实测：`node dist/zcode.cjs --version` → `0.17.0+cq.9.gd4bbd48d.dirty`（当时工作区有未提交
改动，dirty 标记正确亮起）。build.test.mjs +2 用例（describe 解析含 dirty/预发布 tag/垃圾
输入；回退链 describe→rev-parse→dev + 残留 metadata 重建），14/14 过；cli 内 lint 0/0、
oxfmt 干净（tests 有一处折行已修）；architecture:check --changed 0 违规；typecheck 不涉及
（tsconfig 只含 src/**/*，本次纯 .mjs）。

遗留：SEA 二进制要重打（build:sea）用户日常用的 zcode 才会带上新版本号；`--version` 现在
是唯一的 fork 身份出口，桌面端 About/诊断页要不要透传 cliVersion 展示，待用户定。
