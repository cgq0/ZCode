# 2026-10-26 · win

## 21:50 — zcode-serve.ps1 Windows 实测：编码致命 bug + 防护缺失 + staging 两个 Windows 坑

**背景**：昨日（lin 10-25 日记）zcode-webapp 出包批次收尾时留的尾巴——"ps1 仅静态
检查，Windows 实测留给用户"。win 机接手补测，结果第一发就打不响：**ps1 一行都
跑不起来**。整轮共修 4 个 bug，全部实测定罪。

**bug 1（致命）：ps1 无 BOM，中文系统上 PowerShell 5.1 按 GBK 解析直接语法错误。**
报错里 "姝ｇ父" 就是 "正常" 的 UTF-8→GBK 乱码形态；文件头三字节 `23 20 7a` 确认
无 BOM。加 `EF BB BF` 后立即可用。教训：ps1 含非 ASCII 就必须带 BOM，这属于
"静态检查永远发现不了、真机一秒暴露"的类别——昨日的"仅静态检查"恰好漏掉它。

**bug 2：ps1 缺 sh 版 947e1a25 的两个防护，且实测命中假阳性。** 文件头注释写着
"行为与 sh 版一致"，实际不是：手工起一个无 pid 记录的实例占住 3030 后跑 start，
ps1 报"已启动（pid 22048）"且 exit 0——那个进程实际已因 EADDRINUSE 崩溃（新进程
死掉之前，就绪探测先命中了旧实例），pid 文件留下指向死进程的假记录。已补齐并
实测两分支：start 前探测端口被占（无 pid 记录）直接 Write-Error exit 1；stop 后
探测端口真释放，未释放如实警告"存在 pid 文件之外的实例"。stop 警告分支用牺牲
进程（pid 文件指向无关存活进程、端口被手工实例占着）构造验证。注释是主张不是
事实，跨平台"同构"要靠实测对拍。

**bug 3：stage-webapp.mjs 只认 node-pty 源码构建布局，Windows/macOS 本地 staging
直接报缺产物。** Linux CI 无 prebuild，pnpm install 走 node-gyp 源码构建，产物在
`build/Release/`；win/mac 本地 install 直接落 `prebuilds/<plat>-<arch>/`（node-pty
1.1.0 prebuild 跨 ABI，随包 node 22.16.0 实测可加载）。修为两处布局都认，且
prebuild 场景拷贝完整文件集：conpty.node、conpty/（OpenConsole.exe+conpty.dll）、
winpty.dll、winpty-agent.exe、conpty_console_list.node——只拷 pty.node 终端起不来。
拷贝过滤统一为 .node/.dll/.exe/spawn-helper/子目录（Linux 侧等价收窄）。

**bug 4：Git Bash 下 tar 解压炸——MSYS tar 把 "C:\..." 当 host:path 远程语法**
（`tar: Cannot connect to C: resolve failed`；原生 PowerShell 会命中 System32
bsdtar 没事，但本机 PATH 里 Git\usr\bin 在前，从任何 shell spawn 都中招）。修为
Windows 下优先用 `%SystemRoot%\System32\tar.exe`。

**仓库卫生**：staging 产物（274MB）落 `cgq0/webapp/zcode-webapp/` 曾把 lint 拖出
2 个 error（max-lines 打在 26 万/60 万行的单文件 bundle 上）+ 3.4 万告警噪音。
`.gitignore` 加该目录（与 dist/ 同性质；oxlint 尊重 gitignore）后恢复基线
97 警告 0 error。

**验证矩阵**（全真机）：初始 status/stop 幂等；start 后 pid 文件与真实进程一致
（`Start-Process -PassThru` 直接给 node 本体 pid，sh 版"杀壳不杀 node"病史在 ps1
确认不存在）；/api/server-info 与 Web 首页 200；二次 start 跳过；stop 后进程消失、
pid 文件删除、端口无 LISTENING；run 前台模式 200 且不写 pid 文件；两防护分支逐一
触发；staged 原生模块（pty/conpty/conpty_console_list）在随包 node 下加载成功；
修复后全生命周期回归；typecheck / lint（0 error，存量 97 警告）/ architecture:
check --changed 全绿。

**win 机环境备忘**（复跑 staging 前置踩坑链）：无 mise，系统 node 24.13.0 对
mise.toml 的 24.14.0 差 patch 可用；npmjs.org 间歇 ECONNRESET，装依赖走
`--registry=https://registry.npmmirror.com`；electron postinstall 也要
`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`（mise.toml 的 env 无
mise 不生效）；electron postinstall 失败会中断整批 postinstall，node-pty 的
prebuild 落盘受连带，需手动补跑。另：MSYS `$!` 与 Windows pid 是两套空间，
`Get-Process` 认不出 MSYS pid，跨壳测试一律用 PowerShell `Start-Process -PassThru`
拿真 pid。

**未覆盖**：stage-webapp.mjs 改动在 Linux CI 路径（build/Release 源）只做逻辑
等价审查，无 Linux 环境实测；浏览器端完整 E2E（登录态、建终端会话）未跑，
终端功能以原生模块加载 + HTTP 探测为证据，可后续跟进。

**教训**：① ps1 带 BOM 是硬要求，编码类 bug 静态检查免疫；② "与 X 版一致"的
注释不可信，一致是测出来的；③ Windows 上三套坑叠罗汉——代码页、MSYS 工具链
（tar/pid）、npm 镜像，跨 shell 行为差异要在真机对拍清单里逐项过。
