## 06:48 — dev 分支落地；新分支首推的 affected 基线坑

执行 10-21 裁决①：`dev` 分支从 main（cef241e9）建出并推送，`git push -u origin dev`。
零 CI 实证：推送后 GitHub API `actions/runs` 仍为既有 5 次，全在 main，dev 无新 run，
与 10-21 推导一致。后续工作流：日常改动都在 dev 上提交推送，验证 OK 后再合回 main；
release-cli 触发只有 `push: main` 且 paths-ignore 排除 cgq0/** 与 *.md，
本条日记本身即使随 dev 合入 main 也不会触发 CI。

坑：新分支**首次**推送会被 pre-push hook 拦下——`test:unit:affected --scope push`
的新分支基线按合同只用 `origin/staging`（docs/testing/pre-push-hook.md：不猜测其他
分支），而本 fork 没有 staging，rev-parse 失败 exit 2。解法用文档预留的显式基线：
`ZCODE_AFFECTED_TEST_BASE=origin/main git push`。之后 dev 已存在于 origin，走 hook
remote SHA 基线，不再需要该变量。下次再建任何新分支首推时同样适用。

## 07:40 — CLI TUI 三项易用性修复：spec 定稿 + 交接

用户报告三问题并问工作量：①启动后右下角上下文徽标不显示（首个响应完成才出现，
resume 同样）②Ctrl+J 不能换行 ③无 /exit /quit。评估 1~1.5 天，逐项调查到根因级：

- ①是 10-21 a2902559 的遗留缺口：徽标需要 used（仅 ModelComplete 写）+ window
  （仅 session_created/model_selected 写），冷恢复合成事件不带 usage，故 resume 后
  照样隐藏到首轮 ModelComplete。方案=启动元数据 + /new + /resume 三处权威源播种，
  事件仍唯一权威。关键坑：app-result.ts 的 resetSessionProjection 清空块在
  projection merge 之后，顺序必须对调。
- ②根因一行：opentui 把 Ctrl+J(LF) 解析为裸 linefeed（无 ctrl 位），编辑器默认就是
  newline，是我们的 PROMPT_TEXTAREA_KEY_BINDINGS 把它覆盖成 submit。
- ③命令链路全现成，加 exit/quit 分支 + result.exit 标志 + applyResult 消费。

产出：三份 spec（docs/superpowers/specs/2026-10-22-{tui-ctrl-j-newline,
cli-slash-exit-quit,tui-context-badge-startup-seeding}-design.md）+ 交接文档
（cgq0/docs/plan/2026-10-22-01-cli-tui-usability-handoff.md，含环境备注/验证清单/
决策表）。代码零改动，待另机续跑。所有 spec 标识符已对照源码机械核验。
